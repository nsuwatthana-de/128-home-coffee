# LITTLE DAY CAFE

ระบบบริหารร้านคาเฟ่ขนาดเล็ก: สั่งผ่าน QR ที่โต๊ะ หลังร้าน (POS, ออเดอร์, สินค้า, โต๊ะและ QR, วัตถุดิบ, รายงาน) และจอครัว

แผนและสถาปัตยกรรม: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## ความสามารถ

| ส่วน | สิ่งที่ทำได้ |
|---|---|
| ลูกค้า | ดูเมนู เลือกตัวเลือก (ขนาด หวาน น้ำแข็ง นม ช็อต) สั่งที่โต๊ะด้วย QR หรือกลับบ้าน ชำระเงินสดหรือ PromptPay ติดตามสถานะ |
| หลังร้าน | ขายหน้าร้าน ยืนยันการชำระ (เงินสด / PromptPay) ยกเลิกออเดอร์ สินค้าเปิด-ปิดขาย สร้าง QR โต๊ะ (token ใหม่ทุกครั้ง) |
| วัตถุดิบ | สต็อก ปรับยอด (รับเข้า เสีย) สูตรสินค้า ตัดสต็อกอัตโนมัติและคืนเมื่อยกเลิก แจ้งเตือนใกล้หมด |
| รายงาน | รายรับ ต้นทุน กำไรขั้นต้น กำไรสุทธิโดยประมาณ สินค้าขายดี ยอดตามหมวด รายจ่าย ส่งออก CSV |
| จอครัว | แสดงออเดอร์แบบเรียลไทม์ กรองตามสถานี แจ้งเสียงเมื่อมีออเดอร์ใหม่ |

## เริ่มใช้งานในเครื่อง (โหมดทดลอง)

ไม่ต้องตั้งค่าอะไรเพิ่ม ข้อมูลเก็บในเบราว์เซอร์นี้เท่านั้น และไม่มีการตรวจรหัสผ่าน

```bash
npm install
npm run dev          # http://localhost:5173
```

เข้า `/login` แล้วเลือกบทบาท (เจ้าของ พนักงาน ครัว) เพื่อทดลอง ไปที่ "โต๊ะและ QR" เพื่อสร้าง QR แล้วเปิดลิงก์ที่แสดง เพื่อสั่งจากมุมมองลูกค้า

## ทดสอบ

```bash
npm run typecheck    # ตรวจชนิดข้อมูล
npm test             # unit test ของ domain และชั้นข้อมูลในเครื่อง (22 รายการ)
npm run test:db      # ทดสอบ schema, RLS และ function ของ PostgreSQL จริง (ผ่าน PGlite)
npm run build        # typecheck + build production
```

## ตั้งค่า Supabase (โหมดใช้งานจริง)

1. สร้างโปรเจกต์ที่ supabase.com
2. ไปที่ **SQL Editor** รัน `supabase/schema.sql` (ทั้งไฟล์ ครั้งเดียว)
3. **Authentication > Users** สร้างบัญชีพนักงาน (อีเมล + รหัสผ่าน)
4. ใน **SQL Editor** กำหนดบทบาทให้บัญชีนั้น (ตัวอย่างเจ้าของ):
   ```sql
   insert into profiles (id, role, display_name)
   select id, 'owner', 'เจ้าของร้าน' from auth.users where email = 'owner@example.com';
   ```
   บทบาทที่ใช้ได้: `owner`, `staff`, `kitchen`
5. ใส่ค่าใน `.env.local` (คัดลอกจาก `.env.example`):
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
   **ห้ามใส่ service role key ในไฟล์นี้หรือในโค้ดฝั่งหน้าเว็บ**
6. ตั้งค่าข้อมูลร้านในหน้า "ตั้งค่า" (ชื่อร้าน และ PromptPay ID สำหรับสร้าง QR ชำระเงิน)

ข้อมูลตัวอย่าง (หมวดหมู่ สินค้า วัตถุดิบ สูตร) ไม่ได้ใส่ให้อัตโนมัติในโหมดใช้งานจริง ให้เพิ่มผ่านหน้าสินค้าและวัตถุดิบ

## Deploy (Vercel)

- ตั้ง **Root Directory** เป็น `little-day-cafe`
- Framework: Vite (ตั้งค่าไว้ใน `vercel.json` แล้ว รวม rewrite ของ SPA)
- Environment Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
- หน้าลูกค้าเปิดได้โดยไม่ล็อกอิน หน้าหลังร้านต้องล็อกอินด้วยบัญชีที่มีบทบาทใน `profiles`

## ความปลอดภัย

- ราคา ยอดรวม และการตัดสต็อกคำนวณใน function ของฐานข้อมูล (`create_order`) ไม่เชื่อค่าจากหน้าเว็บ
- token ของโต๊ะเก็บเป็น SHA-256 hash และหมุนใหม่ได้ QR เดิมจะใช้ไม่ได้ทันที
- ลูกค้าอ่านข้อมูลออเดอร์ได้เฉพาะผ่าน `get_order_json(id)` ที่ใช้ uuid ที่เดาไม่ได้
- RLS ป้องกันตารางทั้งหมด การเปลี่ยนสถานะ การยืนยันชำระ และการปรับสต็อกต้องผ่าน function ที่ตรวจบทบาท
- ยืนยันการชำระได้ครั้งเดียวต่อออเดอร์ (ทั้ง function และ unique index)
- การยืนยัน PromptPay เป็นการตรวจยอดด้วยพนักงานเอง ระบบไม่ยืนยันจากภาพสลิปที่ลูกค้าส่งมา

## ข้อจำกัดที่ยังมี

- ยังไม่ได้เชื่อม PromptPay แบบตรวจยอดอัตโนมัติ (ต้องใช้ผู้ให้บริการ payment gateway)
- การแก้ตัวเลือกสินค้า (ขนาด หวาน ฯลฯ) ยังทำผ่านฐานข้อมูลโดยตรง ยังไม่มีหน้าจอ
- โปรโมชันและส่วนลด เป็น V2 ตามแผน ยังไม่มีการทำงาน
- การคืนเงินให้ออเดอร์ที่ชำระแล้วยังไม่รองรับ (ระบบจะไม่ให้ยกเลิกออเดอร์ที่ชำระแล้ว)
- เลขออเดอร์ใช้ sequence จึงอาจมีช่องว่างเมื่อมีออเดอร์ที่ถูกปฏิเสธ
- โหมดใช้งานจริงกับ Supabase ยังไม่ได้ทดสอบกับโปรเจกต์ Supabase จริง (ทดสอบ SQL ด้วย PostgreSQL ในเครื่องแล้ว)
